# 芍药田：来源、实现与验证边界

> 2026-09-30。基线 `df9d1e102c26d0c95111b9ea7d48afe0e23a22f3`；版本仍为0.29.0。只处理 `peony_field` 一项。最终核验与失败见 [当前状态](current-status.md)。

## 身份、来源与补完

[T：三月精OSP第14话社区转录](https://thbwiki.cc/东方三月精_～_Oriental_Sacred_Place./第十四话)的P8提供山地语境，P14—16出现芍药田和永远亭管理告示；[C：永远亭场景索引](https://thbwiki.cc/永远亭)作辅助。T是原作文字的社区转录，不是直接取得原书插图；本轮未做原图测绘。

这里是芍药田，不是断崖上的京丸牡丹。永远亭的管理关系不等于把永远亭宅邸、诊疗所或三妖精住所迁来。地点身份有转录依据；选址、321丛植物的花形花色、五带花畦、田间小径、围栏、作业棚、篮筐和排水布局都是本项目P补完。芍药模型是造型近似，不宣称品种或植物学精确复刻。

原始 `data/atlas.json` 的候选／U／HOLD记录原样保留。`data/peony.json` 增加显式 `verifiedLocationCorrections`，只在旧值逐项匹配且已附T来源时更新构建中的事实、类型、证据、出处和施工阶段。禁止该机制修改坐标或无条件覆盖后来研究；11项独立Python测试检查陈旧旧值、未知地点、来源缺失、非T来源及越权字段。普通 `locationUpdates` 的允许字段没有扩大。

## 实际源码与场景

`src/peony.js` 与 `src/peony-renderer.js` 经 `project.json` 注册。原来这一带只有公共草坡和旧树；未改原地形、原树、人物、旧地区源码或总览源包。

五带种植区被中央通路分成十段，321丛芍药共用三种叶／花原型；空间分批实例化，38米切换远档，轻量档使用远档。每丛两枝，642条叶／花实例记录不等于642丛。近景花瓣使用圆润曲面和解析法线，区别于初稿尖锐平面。新增8棵边缘小树与少量灌草，不复制神社植物模块。

作业棚是开放结构，屋面有厚度、柱脚入地、四条台腿承托桌面。初稿台腿悬空已修；轻量档会隐藏桌台与篮筐等props，因此只剩棚体，不是假装完整室内。管理告示复用原有纹理创建／释放流程。没有新增灯光、独立动画时钟、猫／人物、采收系统或药用机制。

公共来路与中央支路按实际近远档地形三角面采样，共4条常驻记录。来路从圣域已有点 `[-1430,-884]` 接出，方向、宽度、色彩和高度渐接；材质复用克隆的现有山路材质，避免仅顶点颜色匹配而受光仍断层。旧道路本体不改，回收本区详情后道路保留。建筑碰撞和人员寻路未实现；地面模式仍沿原地形高度，而非沿新道路碰撞面。

## 复测入口与失败保留

```sh
python tools/build.py
python tools/check-evidence-corrections.py
node tools/check.mjs
node tools/audit-landmarks.mjs
# 普通环境用真实HTTP
python tools/check-peony-browser.py
# 本轮本地HTTP受管理策略阻挡，实际使用的替代路径
xvfb-run -a python tools/check-peony-browser.py --content --headed --chromium /usr/bin/chromium
```

浏览器依赖仅用于可选回归。`check-peony-browser.py` 保留严格的上下文事件断言，不能删除它以让测试变绿。两次长会话均在跨区、多次回收及低档切换末段发生一次丢失后恢复；最终成品的正常UI／生产调度补充探针通过且事件为空，但路径较短，不能抵消长会话失败。

最终失败的浏览器日志记录 `GPU process exited unexpectedly: exit_code=512`；cgroup未记录OOM。退出码不说明触发根因，不能据此宣称是驱动、用户设备或Three.js缺陷。共享恢复模块未改，暂停测试调度时仍会停在pending；本区通过的局部操作不等于解决此前Asama历史问题。

## 后续精修

当前远景药圃仍偏规整，坡地外围偏空，部分旧树与新增植被的风格有差距。花瓣、复叶还有几何感，近距离全实例三角形成本明显高于源数组占用；后续应先改善屏幕覆盖相关LOD和稀疏层次，而不是加密花丛掩盖问题。保持现有神社材质／灯光、连续山体及旧树不动。形制仍未获用户美术验收。

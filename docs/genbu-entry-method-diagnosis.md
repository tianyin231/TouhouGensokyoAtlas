# 玄武涧 V2 近岸拒收：表示方式诊断与未实施方案

2026-10-06。当前 `dd991f…` 候选已停止；本文只读源码、原报告与真实原图，不是第三稿实现或验收。主线 `5f30bca` 的运行内容仍是已交付 `b9ff4a3`／208 输入／HTML `c532…`。

## 与命莲寺失败的共同点和区别

玄武涧低位图已经证实：桥口打开、来路落到首板的收益保留，但西岸及水尾近侧出现新的折皱明暗，水尾仍像拉长的平面。图像没有单独证明法线与实际几何各占多少；独立近岸面诊断另存，不应把纸面推断写成实测因果。

当前 [profile](../src/genbu-entry.js) 把两个 Gaussian 岸脚、旧溪内域、桥域、窄水床、道路走廊和落脚圆域顺序混合。随后 `safeShape` 用树根距离回退，`value` 又直接冻结与桥／根支撑相交的原三角顶点。输出高度是 `oldNear + safeShape - previousHeight`，而新法线取 `safeShape` 的有限差分，没有同样计入最终冻结顶点和原近面相对 analytic height 的偏移。这是可直接核对的源码差异；它有产生网格折面及不一致明暗的风险，尚不能单靠源码定位每个亮斑。

水尾先用恒定水位的六个断面生成平片，再与已经生成的地形裁交。裁交使边缘位置有数学接触，却没有让地形网格沿湿边、岸肩与坡脚布线，也不能保证低位看见完整岸床体量。

Sol 后续一次离线近岸诊断首先发现候选近面 1220 的前两点在 Float32 中落到同一 XYZ，形成零面积面，原面非退化；准确记录见 [原退化面报告](genbu-entry-v2-evidence/checks/independent-v2-degenerate-face.json)。它在请求诊断核心之外、仍位于授权 ROI 内，不能据此声称已经解释画内折皱。新表示必须在最终 Float32 输出上拒绝重复点、零面积和极细长的裁分片，不能只在双精度设计点上验证。

同一次有界诊断的[最终摘要](genbu-entry-v2-evidence/checks/independent-v2-west-bank-folds-summary.json)进一步给出实际面证据：西岸原 4 m 共边 `x=-992, z[-544,-540]` 的两侧折角由 **8.638° 增至 59.912°**，端点高差仍为 0；近面 14368 的顶点法线相对实际面最大偏差由 **5.338° 增至 51.093°**。因此真实新折坡与法线不一致同时存在，不能只修法线就宣称消除折皱。检查还列出两片新增零面积 primitive（一片域内、一片 padding），严格结果仍 CLI 1；极小碎片的大角度没有被当作可见大皱折证据。所有观测累计 1.861 s、0 hooks／native／GPU，没有进一步试稿或全网格通过声明。

命莲寺并非同一个法线错误：`f1c1c3…` 版本已经从真实土面累加法线，仍在原陡板构图上留下灰绿垂幕；单个 ring 接单一 crest 的岩面又形成重复宝石。更早 `4e6184…` 的闭合罩体技术通过，却因保留旧陡面、使用连续背脊而像混凝土挡墙。共同问题是**可见的大形仍由旧面、混合权重和事后保护点间接决定，控制网没有先表达完整坡肩—坡面—坡脚或床—岸的空间关系**。改色、增密网格、平滑法线或另罩闭合体，都不能作为下一次新方法的定义。

历史准确依据：命莲寺 terrain 拒收提交 `4c06c33` 的 `docs/myouren-terrain-v2-evidence/astra-review-v2.json`；闭合体拒收提交 `fd08acd` 的 `docs/myouren-rock-clay-v2-review.json`。两份原图本次重新打开，与原拒收说明相符。

## 一种可执行但尚未实施的不同表示

下一方法仍只做玄武涧南口，不默认换区。完整技术包络保留 `x[-1024,-912], z[-584,-480]`；主要造型核心约 `x[-1012,-936], z[-568,-496]`，从两岸外坡脚跨过溪床到另一岸，包含桥口、水尾及首板落脚。外围只承接原面，不能在水边两三米内再挤出一圈墙。核心边界是初拟控制域，须在未来首个轻量截面中核定，不是已完成几何。

用一张**沿溪向分段、横向有语义控制点的约束地表网**直接替换原面。每个横断面明确九条纵向控制线：左外接点、左坡脚、左岸肩、左湿边、床底、右湿边、右岸肩、右坡脚、右外接点。两岸宽度和坡比独立设计；不把对称权重或随机起伏当作自然形体。

| 沿溪控制站 | 固定关系与设计作用 |
| --- | --- |
| `z=-568/-560` | 接原上游与柱脚；原水位、上游设施保持。 |
| 原桥的 `z=-549.951/-546.049` 边界 | 读取原支撑三角边作为固定边界，显式连接两侧断面；不在生成后硬锁散落顶点。 |
| `z=-536/-528` | 两岸完整展开；右侧控制线接原首板前缘及来路全宽，路肩也是网格边。 |
| `z=-524` | 共用原真实水断面，水位保持；岸肩到湿边有明确可读的坡段。 |
| `z=-518/-512/-506/-502` | 表达一个有床底、岸脚和收口的浅洼；先确定闭合洼地，再由水位与地表求湿线，不先拉一条尖叶水片。 |

树根保留域和桥支撑不再是最后一遍 `if` 冻点：它们的实际原三角边在控制网建立时就成为边界，外围截面以足够宽的土坡连接。没有移动树或木板的授权；若固定支撑与拟定坡比冲突，必须调整断面宽度／位置，不能冻结后把高差推给剩下一个格子。

先构造这些控制线之间的面，再作有约束的三角化；避免任意扇形中心点和与岸线无关的整齐格对角。普通土坡法线从最终焊接面求出，只有设计中明确的折坡才拆硬边。水网与岸网共享湿线顶点；真实地面采样、路面和小植物接地均使用同一成品面。保留旧 analytic/near 偏移的查询契约必须明确，不能再让导航走另一套未约束的函数。

近远从同一套控制面派生。核心优先让两档表达同一岸形，外接带各自精确回到原 near/far；原有 LOD 高差不能默认为零，也不能简单把整片 oldFar 换成 near。实现时需要共同裁分原近／远交界，并独立核对真实面，禁止用点距离或声明替代接缝验证。冷层水尾也从同一湿线生成，不能仅修改 native。

## 原范围和预算内的机会与首验门槛

**有合理的实现机会，尚无新预算实测。** 这里没有命莲寺约 30 m 高差被挤在窄翼中的同等限制；南口图中可见的两岸已有展开空间，桥／树位置也已有真实保护资料。原稿通过降原柱显露桥口的部分可以逐项复用，但失败地面与水尾不能整体继承。

原稿已用到 598212 B 长期新增源，不能叠加第二层网格。新方法必须替换它，保持原 record／材质归属，预期不需新 draw；约十余组横断面及支撑边界应比无差别局部加密更集中地使用顶点，但裁分产生的实际三角和保留数据副本仍需计账。可用紧凑同拓扑 `x/z/newY/oldY + indices` 存接地数据，替代当前两份展开三角 contacts；主线程、Worker 临时副本、公共与 native 水面分别列账。此为布局方案，不是已经实现的节省。

第一技术门仍严格为 ≤0.6 MiB 唯一常驻新增源、≤4000 实际提交三角、≤4 全通道调用、0 新纹理；预算不足时减少控制面和裁分开销，不能缩岸宽、偷换保护或放宽限制。原 37/14 柱身份、桥板、树根、路径及上游保持明确对应。

未来首张图继续用原 `genbuOverview` 固定机位：必须同时读出左右岸脚对桥头的连续承托、水尾在浅洼里的收口，以及来路到首板的落地；不能只是蓝片更窄或高柱更矮。通过后，**原 frontLow 与 reverse 仍是必过门**：坡肩到湿边应是少量连续面，没有星形凹痕，水边应看得出床岸高差。不得换机位遮掉此次缺陷；若全景仍看不到这些收益，不先跑长回归。

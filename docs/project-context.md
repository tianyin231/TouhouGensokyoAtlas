## 1. 项目目标

2026-10-03 补充：用户同意先做跨区稳定性诊断、资源生命周期修复及压力回归；本轮验证通过后直接提交到main，无需新建PR。保留既有地区和视觉成果，不把这一轮扩成全图重建或新版本发布。

2026-09-29 补充：用户当前重点是既有主要地区的整体质感，已认可博丽神社精修及可切换夜景，并要求同时兼顾性能和周边环境的连续过渡。后续通常由浏览器 Chat 逐区接手；执行入口为根目录 [AGENTS.md](../AGENTS.md)，具体标准见[画面升级策略](visual-upgrade.md)。这是在保留新版本地区基础上的精修方向，不要求把全图同时重做或统一成神社风格。

在一个网页里建设可以总览、旋转、缩放、近看、检索地点和查看角色关联的幻想乡三维地图。地图覆盖地表、已建地下及相关异界；以原作及有明确身份的同人参考约束位置、连接和建筑。允许逐区迭代，不要求一次生成最终美术，但每轮要真正改善一片大区域。

交付是实际 Three.js HTML 与可维护代码，不是生成效果图。用户曾明确纠正将建图指令误做成概念图的情况。收到明确“动工／实现”指令后应做实现，不连续退回方案推荐和再次征求确认。本项目不是用户另一个经营或战斗游戏分支，不混入旅馆经营、人偶工厂等未授权系统。

## 2. 最新形态：一块连续的大空岛

用户最终明确要求：**整个幻想乡是一整块大的空岛，岛内各大区域有连接地带，正常天空与天气；虚空只在岛外。**这是对早先分块展陈方案的纠正，不可再按旧方案建设。

可以收紧外围无意义范围，保留整圈有厚度的岩土外缘；不能把每个景点各切一刀、做成独立底座。道路连通本身不够，还需要村外田野、林缘、山脚缓坡、河岸和地表材料渐变。加载区域的边界不能成为地形断口。

正常状态不常驻大洞。查看地下时可局部剖开或进入独立空间，恢复后岛面完整。独立仙界和未来天界不是地表总览上必须常驻悬置的小岛；展示位置不能冒称原作海拔。

博丽神社曾被选为材料和光影样板；保留其精修成果，但不能因为“展示风”重新关闭正常天空或切碎全岛。漂亮的干燥日间场景也必须成立。

## 4. 每轮必须保留的体验

全域与近景使用同一套世界关系，允许相机自由观察和不同方向检查；主要建筑不能只有正面。地表与地下不是互不相干的网页。公共道路在地区详情卸载后仍存在，靠近相邻地区应加载细节而不是强行跳回预设机位。

地点目录、别名、角色注记、预设机位、天气／动态开关和截图导出要有真实作用。避免常驻大段解说、重复操作提示、空按钮，以及必须靠大字招牌才能辨认的场景。细节和考据放进点开后的资料，而不是压满画面。

角色应采用原作立绘或该版本真实存在的像素绘；只标关联位置，不自动承诺会走动和交互。人物表不等于全系列角色穷尽。职责／活动关联与住所需区分；八云紫未确认的住宅位置保持未知。图片加载失败应明确说明，不用同人／生成图冒充原图。

| 兽道人物太少 | 补莉格露、露米娅、橙等同人访客／本作关联，响子保留命莲寺主关联与有出处的道路演出关联 |

| 地下长廊空、缺层次 | 参考指定同人，做实际柱列、梁架、顶、灯、临水栏杆、横桥、莲池与尽端梦殿，而非裸通道 |
| 只在地区中心摆模型，中间生硬 | 把过渡地带作为正式场景内容，不能只加一条同宽色带道路 |
| 性能下降 | 总览简化、按区生成与回收、限制局部灯和反射；不能靠删已接受模型获得低数字 |
| 黑色虚空、多块独立空岛 | 用户否定。现在保留一个连续地表、正常天空天气，只在外围留虚空 |

## 7. 维护优先级

不丢旧成果与不误读最新需求，优先于增加新地名。接着是地区之间连贯、主要体量和材料光影，再是有因果关系的动态，最后才是高成本特效。

用户接受逐区精修，但不接受用“模型很多”“通过很多测试”“已经有入口”替代可见完成度。继续做新区域前，应确认上轮代码实际可重建。仓库保持干净：只留下当前必要代码、构建源资源和精简知识文档；历史产物用标签／Release管理，不搬运旧版HTML、ZIP和整批截图。

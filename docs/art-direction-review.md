# 画面方向重审

> 2026-11-05 记录，尚未开始实施。本文只记录问题和后续工作方式，方向假设全部等待用户确认。涉及画面审美时，本文优先于 [美术规范](art-and-modeling.md)、[画面升级策略](visual-upgrade.md) 和 [需求与决策](project-context.md) 中的同类描述。

## 1. 用户的判断

2026-11-05 用户针对项目当前画面明确指出：

- 画面风格有很大缺陷。
- 区域之间的衔接有问题。
- 画面呈现效果不好。
- 生机感、动态感和幻想乡的感觉基本找不到。
- 现有文档不能全信，旧文档作者的审美不好，这才是接下来要优化的方向。

所以问题不只是“还没做完”。现在的规范本身可能就在把画面引向错误的方向，不能继续只按旧规范逐项补齐。优化的道路还很长，这是用户对现状的定性，不要用通过的检查项或帧率冲淡它。

## 2. 旧文档怎么用

旧文档不废弃，但要分开看。判断标准是：这条内容是事实、用户的决定，还是旧作者的审美。

| 类别 | 处理 | 例子 |
|---|---|---|
| 用户明确做过的决定 | 继续有效，只有用户能改 | 一整块连续大空岛；默认正常天空；保留魔法森林等已建成果；地下用可逆剖切或独立空间 |
| 世界观与出处 | 继续有效，实施时仍要核对来源 | `world-reference.md` 的地理约束、时代边界、`P` 补完标记 |
| 人物规则 | 继续有效 | 有名人物只用可核验的原作图，不用同人或生成图冒充 |
| 工程约束 | 继续有效，但它们只说明“能不能做”，不说明“好不好看” | 按区构建、回收、保护散列、`check.mjs` |
| 旧作者的审美描述 | **不再作为依据，只当历史记录** | 见下表 |
| 用户认可过的具体成果 | 成果继续保留；“照此标准做其他地区”是旧文档的推论，待用户确认 | 博丽神社试点 |

下面这些旧说法不能再直接当作验收标准。这里不是说它们一定错，而是说它们要重新经过用户判断。

| 旧说法 | 来源 | 需要重审的原因 |
|---|---|---|
| “精致的风格化微缩三维世界”“干净色块” | `art-and-modeling.md` 第1节 | 这是在定义整体画风。现在的模型感、摆件感可能正源于此 |
| “克制冷暖光”“干燥木石保持克制反光” | `art-and-modeling.md`、`visual-upgrade.md` | “克制”被用得太宽，容易让画面平淡，缺少情绪 |
| “大范围持续动态要轻”，落叶、鸟兽、炊烟只“局部、偶发” | `art-and-modeling.md` 第7节 | 与用户指出的缺少生机感和动态感直接相关 |
| 优先级：连贯、体量材质，然后才是动态，最后是特效 | `project-context.md` 第7节 | 把生机放在最后，可能正是一直做不到的原因 |
| “关闭雨、Bloom 和 AO 后仍应成立”“晴天是基础验收条件” | `visual-upgrade.md` | 作为结构底线可以留，但不能把朴素晴天当成目标画面 |
| 参考图的取舍（微缩街景、体素大场景） | `project-context.md` 第3节 | 那张表是旧作者的解读，参考方向需要重新定 |

连接地带的路线清单（`art-and-modeling.md` 第3节）里的地理关系可以继续参考，但它写得再清楚也没有产生好的衔接，说明光列路线不够。

## 3. 现状问题

以下观察来自 2026-11-04 的真实 WebGL 画面，括号内是可复现的预设机位。这是技术上的诊断，最终以用户的判断为准。

### 风格

- 整体更像桌面地图或沙盘模型，不像一个可以身处其中的地方（`diorama`）。
- 全岛几乎是同一种绿，色彩上缺少主次和记忆点（`diorama`、`panorama`）。
- 岛体侧面是一圈平直的切面，像切开的蛋糕（`diorama`）。
- 山体仍是圆润的锥形（`diorama`、`mountain`），旧规范明确反对过，但没有落实。

### 衔接

- 地区是贴在草地上的几何形状：太阳花田和无名之丘是椭圆，魔法森林是圆形，人里是一块长方形浅色地面，边缘只做了模糊羽化（`diorama`、`panorama`）。
- 地区之间大多是空草坪，没有可以称为“路上风景”的内容。
- 树在山坡上分布过于均匀，看起来像波点（`panorama`）。
- 森林入口读起来像公园：大片修剪过的草地上等距站着树（`forest`），不是潮湿的原始林。
- 地形块之间有可见的硬接缝。例如 `x=-768` 处两侧材质不同，阴影在此错位（`forest`）。

### 画面呈现

- 这轮加入了日光比、空气透视和全岛地形投影，体积感有改善，但画面仍缺少情绪：时段、天气只是几个固定状态，没有光影事件。
- 水面偏暗偏平。
- 总览时云海是一张平面，顶部有竖向条纹。
- 河道下游有深蓝锯齿（`panorama`）。

### 生机与动态

2026-11-05 用中英文关键词检索了全部 `src/*.js`，现状如下。检索不到不等于绝对没有，动手前再核对一次。

| 已有 | 没有（未检索到） |
|---|---|
| 水面、瀑布、云、雨 | 蝴蝶、蜻蜓、萤火虫 |
| 竹叶和部分树叶的轻微摆动 | 飞鸟、乌鸦（华扇仙界只有鸟舍场景） |
| 部分花瓣与花朵 | 蒲公英、花粉这类空气中的漂浮物 |
| 索道等固定机械 | 妖精 |
| 个别地区的蒸汽、烟雾 | 普通村民、行人 |
| 少量不会动的布景动物：迷途之家的猫、竹林空地的兔子 | 日出、时段的连续变化 |
| | 全局季节（只有冥界冬庭这类单区选景） |

另外，人物是叠在画布上的网页图钉（`src/characters.js`），不在三维场景里。世界里几乎没有会自己活动的生命，这很可能是缺少生机的主要原因。

### 幻想乡的感觉

这一项最难量化，也最不该由实现者自己下结论。目前的情况是：地标按地理关系摆对了，但把名字和图钉关掉后，很难认出这里是幻想乡，更像一个通用的日式风景沙盘。

## 4. 本轮光影层的定位

`src/render-look.js`（2026-11-04）解决的是技术问题，不等于方向正确：

- 它的颜色是**对照旧画面收回来的**。把总览绿色饱和度压回去，用的参照正是用户现在否定的审美。这些数值以后可以大胆改，不要当成定稿。
- `visual-upgrade.md` 里记录的“荧光”“洗淡”等教训只说明当时的技术原因，不是美术结论。
- 帧率、加载和保护机制的成果与审美无关，继续有效。

## 5. 以后怎么推进

1. **先定方向，再动手。** 动手前先和用户确认第6节的问题。方向不清时不写代码。
2. **参考要具体。** 由用户选定参考画面，逐条说清楚要它的什么。不要再由实现者用抽象词替用户定义审美。
3. **做一段完整的样板，不再摊到全图。** 选一条能走的路线，把地形、植被、光影、动态放在一起做到位，让用户看实际运行效果。候选：人里 → 香霖堂 → 魔法森林。
4. **用户的眼睛是唯一的美术验收。** `check.mjs`、帧率、模型数量和截图数量都不算美术通过。
5. **性能是约束，不是方向。** 先证明效果值得，再想办法降成本。不要因为担心性能，提前把动态和层次砍掉。
6. **工程上的前提。** 改全局光影、地表材质时，保护散列的链条很长（`engineering.md` 第6节）。方向确定后，应先评估哪些保护项需要显式更新，不要让它们反过来决定审美。

实施后用用户的结论更新本文。被证明无效的做法也要写下来。

## 6. 待用户确认

- **参考：** 有没有特别想要的画面？可以是某款游戏、动画、官方插画，或某张同人图的氛围（只借鉴感觉，不拿它的素材）。
- **“幻想乡的感觉”具体指什么？** 下面只是待确认的假设，不是结论：
  - 被遗忘之物聚集的怀旧感
  - 人与妖怪共处的日常
  - 强烈的四季变化
  - 黄昏这类“逢魔时”的氛围
  - 结界与异变带来的非现实感
- **季节：** 要不要全图有季节变化，还是固定某个季节？
- **视角：** 主要是飞在空中俯瞰，还是走进场景里？这会决定细节该放在哪一层。
- **空岛外观：** 悬浮岛的形式是用户定的，但岛体边缘怎么呈现（现在的切面）能不能重新设计？
- **神社试点：** 作为保留成果没问题。它还是其他地区的完成度标准吗？
- **人物：** 有名人物要不要进入三维场景，还是只增加无名的村民、妖精和小动物？前者受原作立绘规则约束。
- **优先级：** 是否把动态和生机提到体量材质之前，甚至一起做？

## 7. 试片记录（2026-11-05）

**结论：用户看过第二轮后定稿“二次元强化”这一版，原话是“这个二次元画风不错，就定这个画风了，之后再打磨一下清晰度就更好了”。** 上文记录的画面缺陷里，画风这一项到此确定方向；衔接、生机、体量等问题仍未解决。

- **第一轮：** 用户看过可切换的真实 WebGL 试片后，对“动画背景”方向的反馈是“这个风格不错，甚至可以再二次元一些，融入感更强”。“和风绘卷”未被选中。
- **第二轮：** 加入分层光影、团块状树冠、偏天色的空气透视、白天柔光、光束、彩色轮廓线、手绘积云、光点和镜头缓动。
- **正式实现：** 画风在 `src/render-look.js`，镜头缓动在 `src/camera-feel.js`，都不改受保护的 `src/renderer.js`、`src/camera.js`、`src/landscape-renderer.js`、`src/app.js`。试片的按键和未选中的画风已删除。动画帧率保持原来的 30 帧、总览 15 帧，没有沿用试片的 60 帧。
- **清晰度：** 用户看过三档可切换试片后决定默认“清晰”，设置面板可选“更清晰”（`opt-sharper`，由 `src/render-look.js` 在运行时加入，不改受保护的页面文件）。“定稿版”的滤镜强度不再保留。
- **神社：** 地表核心和 `hakurei*` 材质没有改动，但后期画风层也作用于神社画面。用户定稿时没有对神社单独提出异议，也没有单独确认，后续精修神社时要再确认一次。

试片中查实的问题，正式实现时要处理：

- 种植树的 LOD 按批次中心距离选择。批次半径可达约 370 米，镜头在批次边缘时近处的树也会用六边形低模（`src/renderer.js` 的 `levelFor`）。试片用“距离减半径”绕过，三角形数在六个固定机位中五个增加 12% 到 112%，全岛总览不变。正式实现应改成按实例或更小的格子选择。
- `overview:village:trees` 是人里的总览替身树，共 322 棵，没有近景版本。镜头离它约 54 米时仍显示低模，需要改成按相机距离加载，而不是只按焦点地区加载。
- 地表绘制用的 44 米周期噪声在俯瞰时会形成格子。试片用旋转加不同周期的两层噪声消除；单层大幅度扭曲会产生等高线花纹，不要采用。
- 地平线云的竖向条纹来自 `makeNaturalSky` 的 `d.xz/max(.22,d.y+.12)`：分母被钳住后，云的坐标在贴近地平线处几乎不随仰角变化。
- 绘画滤镜会抹掉几像素大小的粒子，光点类效果要在后期之后叠加。
- 现状非低画质已有 2 倍 MSAA（`src/renderer.js` 的 `setSize`），试片用 4 倍。

## 8. 异界画风延伸（2026-11-06）

用户要求把定稿画风推到其他空间，并考量场景布置、“传播”、美术与原著还原度。用户随后确认“传播”就是穿帮，具体指部分模型放错了位置，并要求把隙间转场做得更有代入感。用户看过改前改后对比后的反馈是“改的不错，明显比改之前更好”，这一方向保留。

- **做法：** 后期画风按空间换参数，不套地表数值。天空换成手绘网格，事件变体分开：白玉楼飘雪、天界 TH155、绯想天、封存月都、表月、华扇宅夜景。
- **穿帮：** 216 个异界机位逐张看过，修了 6 个贴墙或在洞外的机位（`CAMERA_FIXES`，只改相机）。地形尽头淡入雾色。旧地狱与虹龙洞全貌清掉雾，能看清结构。
- **放错位置的模型：** 用脚本扫了全部 423 个机位：悬空、埋地、树穿屋顶、路钻进房子，以及机位被遮挡。修了五处。魔界法界两座钟楼的石块悬在半空（`src/makai.js` 改成落地，基线手工更新）。冥界台阶旁的旧幽灵多面体在高画质下隐藏，由公告板灵体代替。仙界山石顶上的黑洞在运行时封口。瀑侧登山道被两根岩肋压住，石阶直接钻进崖石；这两根在显示层拿掉，近景和总览都处理了。`seikiPath`、`mountainTrail`、`shrineDioramaSide`、`genbuColumns` 四个地表机位钻进树冠、贴崖或在地面以下，改了相机。
- **还原度：** 彼岸花连成红毯，幽灵、怨灵和神灵分空间出现（只是无名小灵体的印象，未画具名人物）。玄云海有闪电，表月是黑天灰土。仙界金顶压了瓦垄，群山由金字塔改成平滑体量。
- **转场：** 切换空间分三段：隙间撕开吞掉旧画面、满屏眼睛里等新场景模型就绪（最多 2.4 秒）、再沿斜线裂开。模型弹出被挡在幕后。打开时派发 `atlas-gap-open` 事件，给到站标题用。关掉动态、低画质、系统要求减少动画或自动化测试时不播放。这是 P 表现，不是原作演出。
- **界面：** 第一轮做了和纸、御札、隙间三套实色主题，用户看后否决：“都有些喧宾夺主了，而且与现在的画风不太搭配”。以后的界面要让场景做主角，静止时不放实色面板，不用高饱和的大块颜色。

这一层解决不了的问题：

- 月之都只有建筑和空地，街面缺少陈设。
- 畜生界的高楼是重复模板，天界的桃树也几乎同形。
- 剖览视图（浅间、风穴等）背景仍是一片纯色。
- 魔界万魔殿侧廊的窗面是大块平涂。

这些要改世界建模，需要逐项更新散列基线。低画质不生成地被和树冠卡片，彼岸花田会退成一片平的红色。

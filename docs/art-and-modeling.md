# 美术、建模与场景验收规范

> 目标由用户参考图与多轮明确修正形成。最新形态是正常天空下的一整块连续幻想乡空岛，不是黑色展厅中的多个独立小岛。地理依据见 [world-reference.md](world-reference.md)。

2026-09-29 的博丽神社试点已获用户认可，作为后续**完成度**参照：有厚度的瓦檐与真实开口、材料尺度清楚、植被有枝干和层次、林缘渐变、日夜光照可逆。各区域保留自己的建筑语言，不照搬神社模型。新增可选夜晚不改变默认日间要求；实现和逐区步骤见[画面升级策略](visual-upgrade.md)。

## 1. 画风目标

采用精致的风格化微缩三维世界：干净色块、清楚轮廓、统一尺度、可信材料反光、克制冷暖光和有设计的生活细节。模型可以简化，但不能以“低模”解释粗糙地形、薄墙、穿插、死黑屋檐或通用房屋换色。

参考街景的价值在材料、光照、空气和透视，而不是雨丝本身。关闭雨、泛光和景深后，场景仍应成立。晴天是有效默认状态，地下则按自身环境照明，不强行套用地表天气。

## 2. 大场景先后顺序

先做地理约束与路线，再做主地貌、建筑群轮廓和林带；中景成立后才加入门窗、瓦、栏杆、草花及器具。每轮锁定具体大区和验收镜头，不为了增大模型数量同时重造全世界。

| 距离 | 必须读得出的内容 | 不必同时保留的成本 |
|---|---|---|
| 全域 | 单一岛体、主山脉、水系、区域相对位置和地标剪影 | 每朵花瓣、每根竹节、每块屋瓦 |
| 区域 | 街区与庭院组织、谷地与坡脚、岸线变化、入口与道路 | 全部房间和微小陈设 |
| 近景 | 屋檐厚度、门窗进深、柱脚、台阶承托、材料区别 | 镜头外全图高精度模型 |

先改善占屏幕大面积的山坡、岸线、林冠和路网，不在粗大地形上不断叠小石头／粒子来伪装完成度。远山需要主脊、侧脊、沟谷与山脚，不是一排相同圆锥。

## 3. 连接地带是正式资产

每个大区都有核心、边缘和过渡，区域归属标签只服务加载，不能变成地形断裂。

- 人里至森林：村口铺路／田埂 → 草地疏林 → 香霖堂店前空地 → 混生林缘 → 深林。
- 人里至竹林：田野 → 散竹与灌木 → 斜坡竹群 → 密竹回环，不能一条直线同时换树种和地色。
- 人里至神社：乡间路 → 兽道林带／溪桥 → 山脚 → 石阶与平台 → 神社参道。
- 湖岸至红魔馆：湿润自然岸 → 疏林来路 → 整理过的门前地 → 规整庭园。
- 山麓至守矢：缓坡 → 溪谷／瀑布 → 折返山道 → 高处湖盆 → 神社参拜轴线。
- 旧都至地灵殿：街区灯火与排水渠 → 较静的庭道／台阶 → 前庭与主殿；继续下行后再进入炽热设施，不在每处铺熔岩。

高度与坡度都要连续。道路随地形绕行、收窄和转折；桥头有落脚面，栏杆为阶梯与入口留口。地面从土、碎石、落叶到铺装平滑过渡，岸边湿润与远处干地有区别。连接道路在详情卸载后继续保留。

## 4. 建筑必须有自己的结构语言

| 建筑群 | 辨识重点 |
|---|---|
| 博丽神社 | 登高参道、鸟居、拜殿、架空缘廊、注连绳／纸垂、侧后生活空间 |
| 守矢神社 | 高湖、御柱、大注连绳、低鸟居与高正殿，不能放大博丽模板代替 |
| 命莲寺 | 山门、逐级台地、正殿红幡、钟楼、附属屋、寺后墓地 |
| 地下梦殿 | 狭路至宽敞洞室、真正连续的柱廊／梁顶、临水栏杆、莲池和八角主体 |
| 红魔馆 | 红砖／长窗、三层主楼与不同进深翼楼、钟塔、铁门和庭园 |
| 地灵殿 | 西洋拱门、彩窗、棋盘／彩绘地嵌、柱廊与吊灯，外部与已建大堂都保护 |
| 香霖堂 | 店面、白墙土藏、连接廊和有选择的旧物陈列 |
| 爱丽丝宅／雾雨邸 | 整洁小洋馆与侧塔，对比旧屋、烟囱、工作棚和收藏物；不是同模板换色 |
| 永远亭 | 横向延展、院门、两翼和缘廊、竹林遮蔽；不把特殊内部空间无限放大到地表 |
| 夜雀屋／旧都铺面 | 实际开口、吧台／浅展示区、棚架和货物类型；不是封闭墙上贴招牌 |

重要可见边有厚度或适度倒角。檐下、窗框、墙基和柱脚有进深；平台真正被山体／基础承托。四面、背侧和低角度都能检查，未见原作背面明确标P。场景不靠新增大字和乱摆杂物“精修”。

## 5. 植物与小物件

竹子有收分、竹节、倾斜、分枝与窄叶；古木有根系和分叉，树冠高低和密度成组；向日葵、铃兰、彼岸花各用可辨识结构，而非同模型换色。无缘塚紫樱与地形形成围合，不照抄命莲寺墓位排布。玄武涧的六角柱岩必须构成崖壁与溪床，不是任意散布的石柱装饰。

实例化用来降低重复提交，不是均匀撒点的理由。植物避让道路中心、台阶、建筑门口、水面和重要机位；低草和石体可以侵入不规则边缘，但不能挡住全部通路。近远版本保留群落轮廓，临界距离避免反复切换。

小物件先服务用途：茶器、布匹、书册、厨具、木料和维修器材应对应所在地。普通环境动物不自动当作角色 NPC；不把未知住宅强行配给现有角色。

## 6. 材质和光影

木、瓦、石、漆、金属、纸门、水体分别调粗糙度与反射。纹理用来支持结构，不用大面积杂色、伪木纹和噪点代替真实深浅层次。颜色纹理与法线／粗糙度等非颜色数据分开处理，顶点颜色与灯光计算保持线性；最终输出只做一次正确转换。[Three.js颜色管理](https://threejs.org/manual/pages/color-management.html)

地表共享稳定的太阳方向、天空和天气。进入竹林不能使远处山坡的太阳整体换色；局部阴暗来自林冠、遮挡、坡向和受限雾效。阴影分为粗地形投影、建筑／树木投影和近景接触明暗，不让一张阴影图同时负责整岛与每片瓦。

暮色可突出暖纸门与廊灯，但不是全图压黑再堆高泛光。总览少用或关闭景深，保留可读区域关系。地下用旧都暖灯、宫殿较静的彩窗、灼热区高温光和血池冷暗色形成差异；不能全部涂同一种红。

水面不仅有倒影，还需要岸线、浅深差、石头接触、跌落边缘与水沫。几何水幕／程序波纹必须如实称作效果，不宣称流体模拟。精度和反射预算见 [engineering.md](engineering.md)。

## 7. 动态的因果与节奏

共享主要风向与阵风节奏，不同植物、高度、遮挡和材质响应不同。旗帜、暖帘、竹叶和邻近草丛不能各自朝相反方向机械摇摆。大范围持续动态要轻；落叶、鸟／兔活动和炊烟可局部、偶发。

雨天是天空、雾、受光与局部雨幕的整体状态，不只是几条线；但本项目不以物理积水系统作为当前画风成立的前提。地下不照搬地表雨。暂停要保留场景时间，恢复继续；不可将时钟归零造成缆厢和水面跳相位。

高质量近景的顶点风动应检查其阴影是否跟随；远景允许明确的简化阴影。不要让全部人物大头像持续上下飘动充当生活感。

## 8. 视觉验收

至少检查全域、区域三分之四、近景正面、背侧、低角度地基与连续路径。沿路录制不断开的移动过程，检查地形／材质突变、LOD跳变、穿树、断桥和切层恢复。固定灯光、天气、相机、分辨率和画质做前后对照。

截图必须来自本轮交付的实际 WebGL 场景，不得用生成图片补洞。关闭地名和人物层也能辨识地点；关闭泛光后结构仍然成立。原作图片加载失败要单独记录，不用替代图片冒充。软件图形后端的实机截图可以验证渲染，但不能替代真实显卡帧率测试或用户对画风的接受。

# 开发、验收与发布流程

## 1. 以当前Git结构为准

先读 `AGENTS.md`、[需求记忆](project-context.md)、[当前状态](current-status.md)及根目录README，记录Git HEAD和工作树改动。保留用户修改，不重置、不用历史ZIP覆盖当前目录、不强推。

维护者已经将旧地狱和源资源入库，随后完成独立构建迁移。**不得恢复“读取v0.16 HTML生成v0.17”的旧流程，也不得重新上传根目录版本化HTML。**`assets/packs/` 是必需源资源，不能当作临时缓存删除。最新需求仍是正常天空下的一块连续空岛，不回退到黑色分块展台。

## 2. 修改前锁定范围

分清本轮改变地形、路线、模型、材质、人物数据还是渲染器；不修一处顺手重做全世界。维护者的地灵殿大堂、回廊、温泉街、旧血池都已有真实实现，不能按更早计划降回占位。

新增地区需稳定ID、建模入口、`project.json` 的模块顺序、主线程／Worker同实现、非占位几何、公共连接、机位、目录和出处。名称／ID变化同步人物与导航。不通过“有标签”认定已建完；未知坐标不落原点。

原作结论、转录／社区整理、指定同人及P工程补完分开记录，附版本／时代。避免把神灵庙、地灵殿、旧血池、血之湖等不同地点合并。源码与数据内部的历史版本号不随发布版本全局替换。

## 3. 三道独立验收

| 检查 | 回答的问题 |
|---|---|
| 文件与生成内容保护 | 原有源码、关键数组、材料身份和变换是否意外变化？ |
| 地区覆盖 | 模块是否打包并执行，是否有实际近景而非目录／总览／占位？ |
| 运行与视觉 | 最终成品是否可看、可操作、能往返，画面是否达到本轮目标？ |

魔法森林事故说明：与上一版相同，也可能继承上一版的缺口。地区必备表不能从当前缺失的世界自动生成并默认通过。至少保护森林及三建筑、人里、神社、兽道／夜雀屋、红魔馆、山寺／历史长廊／仙界、竹林／永远亭、花地、山地／守矢、无缘塚／玄武涧及当前旧地狱各已建子区。

固定哈希只有经审阅的有意修改才更新，留旧值和理由。测试不能自动刷新期望结果来掩盖回退。近景改了以后还需检查 `assets/packs/` 的总览是否过期，不能以一张近景截图覆盖整个发布状态。

## 4. 当前可执行流程

根目录README要求Python3.10+、Node.js22.x，与CI和`.nvmrc`一致。Node.js24会产生不同的逐字节几何摘要，不应因此刷新基线。无需npm／pip依赖。当前命令：

```sh
python tools/build.py
node tools/check.mjs
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

构建输出版本化HTML、`release.json` 和 `SHA256SUMS.txt` 到忽略的 `dist/`。检查器会拒绝过期输入／产物、一部分脚本和资源错误以及Git跟踪的发布HTML。修改源码后重建，不人工编辑dist文件；模板 `src/index.html` 不能独立预览。

当前检查器会实际生成旧地狱并校验基本数据，但不等于执行了全场景浏览器／视觉／性能检查。历史对话的 `tests/browser016.py`、`tests/runtime-check.py` 等旧套件不在本仓库，不能写成当前可用命令或照搬其通过数。

重建一致性应按当前源码与资源连续构建两次、比较输出SHA和输入清单；差异要解释，不用旧版产物改名。文档整理本身只查源码／链接／差异，不冒称已经执行了这些构建和运行步骤。

## 5. 浏览器和地区回归

实际加载最终HTML，确认Three.js/WebGL2。检查全岛→森林三建筑→神社→新地区→命莲寺历史地下→仙界→地表；旧地狱至少覆盖旧都、温泉、前庭、大堂、回廊、下行、炉心、血池、顶盖和返回。地下不出现地表雨丝，离开后恢复正常天空。

用真实鼠标／键盘／控件检查旋转、缩放、平移、自由镜头、搜索／别名、人物详情、天气、暂停、画质、PNG和JSON导出。快速换区测试旧Worker不回插、镜头不被重定位；多轮往返清理后详情CPU与GPU记录应有界，记录趋势，不宣称永久零泄漏。

跨区资源回归使用 `python tools/check-render-lifecycle-browser.py`，默认真实HTTP、原生Worker、生产帧调度。先以原生 `#view=backdoorSpring` 启动覆盖Worker加载前的无贴图窗面，保存持有程序的只读证据；返回总览清空详情后，执行阴影回程、一轮完整暖场及3轮相同路线。独立CI作业保留报告与失败证据。较长复现可运行 `python tools/check-render-lifecycle-browser.py --cycles 3 --soak-seconds 1200`，持续时长从完整暖场后计，完成当前轮才停止。每轮在相同画质／机位／天气清理后严格比较资源，终点另附有界程序清单；期间任何非主动上下文丢失都失败。最后单独注入一次丢失／恢复，验证环境贴图和后户窗口重建；`--recovery-only` 不执行冷入口预热。注入成功不证明历史丢失已根治。

定位恢复阶段的断言可使用 `--recovery-only`，报告明确标记为仅恢复验证，不代表已完成跨区压力段；不能与 `--soak-seconds` 混用。地面材质可能通过 `scene.environment` 继承贴图，检查时区分隐式继承和显式envMap，不能把合法的null绑定当成旧纹理残留。

每帧工作量回归使用 `python tools/check-frame-work-browser.py`，在真实HTTP与生产调度下检查拖拽、缩放、连续路线、标注开关、人物分组与异界选景。旧版构建可用 `--collect-only --dist <旧版dist> --output <基线目录>` 采集，再对当前构建使用 `--compare-to <基线目录>`；对照要求相同浏览器与设置，并比较标注位置和关联列表。报告中的插桩CPU耗时与工作计数不等于实体GPU帧率。固定机位像素对照单独执行。离线 `tools/check.mjs` 同时覆盖隐藏状态、异步图片、变换恢复、6秒回收边界和预算压力下的共享引用。

固定帧截图与正常动画循环分开验收。确认暂停保持非零相位、恢复继续，水、火星或索道的实际像素／变换变化。标注与局部灯随空间同步。几何采样可以检查绕序、有限值、支撑、水位和路径，不证明每片叶子零穿插。

固定天气、相机、分辨率、DPR与效果开关做前后对照；至少包括总览、正面、背侧／地基和连续连接路线。截图绑定最终产物SHA，不使用生成图修补、不把维护者旧preview说成本次新图。入库只选少量代表图，完整录像和临时结果不堆主分支。

## 6. 性能和失败必须如实报告

分别报告CPU源数组、GPU属性、贴图／渲染目标、浏览器堆和物理显存；未测写未测。统计全部通道，区别首次生成、重访上传和稳定帧。软预算不是硬上限，更新频率目标不是实际FPS，减少精度或关闭特效不算完全相同画质的免费加速。

软件图形后端可验证渲染，不替代硬件和手机验收。`file://` 受策略阻止时记录失败，使用允许的装入／本机HTTP路径不能冒称所有用户设备通过；不关闭管理员安全策略制造成功。原作图片失败与脚本错误分开记录，有URL不等于离线图片已完成。

## 7. 干净提交与发布

日常维护一套当前源码，Git保存历史。只提交本轮必要 `src/`、`data/`、源资源、工具和精简文档；不提交dist、历史HTML／ZIP全集、临时解包目录、下载缓存、全部录像、原图素材合集、字体或个人信息。提交文件用明确名单，不在不清楚工作树时盲目全加。

正式版本按README流程更新 `project.json`，构建／检查／浏览器验收后提交源码，再创建新标签与Release。以 `dist/release.json` 的artifact和tag为准上传当前HTML与校验文件，不使用 `dist/*.html` 混入旧产物；不移动已发布标签或覆盖成品。部署、重写历史或改变许可证需独立授权。

发下载链接之前确认文件存在、可读、非零、版本正确且已写完。发布说明只报告实际通过的检查；预览图存在不证明源码已保存，旧文件改名不是新版本。源码与资源应可重建产物，不依赖聊天沙盒地址或其他会话的临时目录。

## 8. 维护交接文档

完成一轮更新 `current-status.md` 的快照、地区和未测项；需求变化更新 `project-context.md`；新考据补 `world-reference.md`；架构变化补 `engineering.md`。不要给每个版本再拷贝一套文档，避免多个互相矛盾的进度表。

最终交付回答：实际改了什么，凭什么确认有效，还有哪些边界。不得把计划写成完成、历史测试算成本轮，或为了回避失败再次提供不存在的文件链接。

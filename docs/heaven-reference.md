## 2. 独立展示，不改幻想乡地表

`heaven`与`genkumoumi`是两个空多边形、恒等展示变换的工程坐标图。分图属于P组织方式，不代表原作把玄云海与天界规定为两个不相连世界。它们不进入地表`placements`、不改变原山体、不切割幻想乡大空岛；导览切换不标里程，也不假定它们与冥界、仙界、月都在同一物理高度层。

有顶天花原在连续的本地地貌上布置桃林、曲折小径、要石和开放小亭；可从背側及低角度观察岩基。玄云海另建具有肩部和裂面的岩台、成组石体、远处多峰山峦与云层。岩块与远山没有通过单个圆锥复制来充数；形状、密度、距离和所有地形尺寸仍是P。

小亭有台阶、台基、八柱、梁撑、栏杆留口、厚檐、瓦脊、棋桌和茶具，是没有专名的P环境建筑。没有将它命名为天子府邸、天帝宫殿或龙宫。要石采用低伏石体、环绳和纸垂的P造型，不声称是原作唯一形制或有地震物理模拟。

34株桃树带分叉、分组绿冠和果实，区别于月都以花冠为主的树木；花草避开路径和入口。树数、种植网格与桌案陈设不是一设。宴席只在对应机位显示，回到日常后隐藏。

## 3. 天气、作品状态与人物

TH105花原模式显示桃林、小亭与花草；TH155选景改为土石色、浮石及极光，同时隐藏前者的专属景物。两者共用本作展示地形，不宣称两个作品的地图完全同构。

玄云海“绯云征兆”只改变该事件的天空、云色与局部受光，普通机位恢复；天界不出现地表的小雨。原地表的天气和照明选择保留，返回后恢复。云带与极光共用原场景时钟，暂停不清零；它们是程序化景观材质，不是气象、流体或真实极光模拟。

新增天子、衣玖两条人物，总数69。原67位记录及白莲／爱丽丝历史访问逐项保留。TH105人物标记不显示在TH155选景中。新人物的位置在自己的独立坐标图，不按同一X/Z下的幻想乡地表高度抬升。

两位原作肖像均未取得可核验文件，明确显示“原作图待核”及原作文字来源，不填写猜测直链，也不用同人图或生成图替代。原有图像外链仍可能失败，场景不因此被称为全离线人物版。

## 4. 实现入口与预算

`src/heaven.js`在`landmarks.js`之后登记到`project.json.worldBuilders`，同一份代码进入主线程和Worker。`src/heaven-renderer.js`最后继承渲染器，隔离材质、天空、一盏小亭补光和作品状态。相机子类只为新空间开放岩基下方旋转，其他空间和自由镜头行为仍委托原实现；没有修改原`camera.js`。

启动仅追加共1,746,360字节低精度代理，细节由原生Worker按区生成；离开可取消和回收，代理保留。原两份pack.gz以及全部已有地区生成器未改。这些数字是源数组，不是浏览器总堆、物理显存或硬件FPS。广域地形不写入聚焦阴影图，仍有渲染提交成本。

显式目录解析保留原77项，再加3项，得到179条中的80条可导航、99条待处理；不是80项全部竣工。审计版本由构建填入，不再固定为0.21。原冥界检查仅允许未来数量增加并限定自身新增人物切片，旧几何、旧映射和哈希不刷新；新检查精确验证69人物、80导航、原67位记录和22个继承文件。

## 5. 验收与限制

```sh
python tools/build.py
node tools/check.mjs
node tools/audit-landmarks.mjs
# 可选；额外依赖Playwright和Chromium，不属于离线构建依赖
python tools/check-heaven-browser.py
python tools/check-browser.py
```

`check-heaven.mjs`及`heaven-baseline.json`为只读几何与继承检查，测试不自动更新期望。浏览器报告绑定最终HTML的SHA，分别记录脚本／着色器和外链错误。固定帧截图及有限路线采样不代替全世界碰撞、完整录像、长期内存压力或用户美术验收。

本轮实际后端为Chromium144／WebGL2／SwiftShader，使用Xvfb有头浏览器与`--content`装入相同HTML，保留真实Blob Worker。这不是HTTP／file://或真实显卡FPS验证。具体本轮通过项与失败尝试见[当前状态](current-status.md)。源码直接推送，不自动创建Release或改动既有标签。
